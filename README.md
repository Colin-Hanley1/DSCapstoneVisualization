# Atlas

Atlas is a static, client-side US geospatial data viewer for layering CSV, JSON, and GeoJSON data. It is intentionally built with plain HTML, CSS, and JavaScript so it can deploy directly to GitHub Pages with no build step.

## Use it

Open `index.html` in a browser, or enable GitHub Pages for the repository root. Use **Open data…** or **Paste data…** to load a layer. After loading, use **Layer properties** to explicitly define the layer:

The Load data panel also includes a built-in sample gallery covering state tables, CSV points, wide point records, GeoJSON points and multipoints, polygons, lines, multipolygons, and mixed geometry collections. Use **Load all demo layers** to see the supported visual layer types together.

The same panel includes a real reference layer: **PNNL data center buildings** loads the bundled `pnnl_atlas_records.csv` snapshot with 1,237 building-level records. The source is the [PNNL IM3 Open Source Data Center Atlas](https://im3.pnnl.gov/datacenter-atlas/), distributed here through the [Energy Factbook data release](https://energyfactbook.com/data-centers/map/). It is derived from OpenStreetMap, licensed under ODbL, and accompanied by [`ODBL-NOTICE.md`](ODBL-NOTICE.md). The locations are useful for visual reference but are not a complete census, and the dataset does not contain power-demand calculations.

The real-data gallery also includes bundled display snapshots for **EIA electric power plants** (`eia_power_plants_2025.csv`, 16,900 located plant records from the 2025 early release), **HIFLD substations** (`hifld_substations.geojson`, 77,945 nationwide point records), and **USGS public-supply water service areas** (`usgs_public_supply_water_service_areas.geojson`, 18,806 polygons). The substation snapshot was retrieved from this [public HIFLD ArcGIS service copy](https://services6.arcgis.com/OO2s4OoyCZkYJ6oE/arcgis/rest/services/Substations/FeatureServer/0) and covers the country, but HIFLD notes that lower-voltage coverage is incomplete. The map viewport-samples this large point file so it stays responsive, then selects the points in view when you zoom or pan. The water-service file is a public-supply coverage context layer, not a treatment-plant inventory; it is a display derivative of the USGS `WSA_v1.zip`, reprojected to WGS84 and simplified with a 250 m topology-preserving tolerance, so it is appropriate for visual context but not boundary-accurate analysis. EIA warns that the 2025 early release is not fully edited and should not be used for aggregation.

The gallery also includes **Observed groundwater depth · historical**, a compact time-based sample combining representative 2010 and 2022 snapshots from `features_observaed_gwd_CONUS_20012020.csv`, plus the individual 2022 sample. Layers with a usable time field expose a **Time lens** above the map: select a period, scrub through periods, play the sequence, or return to all periods. Date-like fields are grouped to month; year-only fields remain annual. These samples are intended for visual exploration only.

The gallery also includes **USGS groundwater · nationwide latest available**, a refreshable map-ready snapshot of the latest available daily depth-to-water value for each geolocated monitoring site. To refresh it locally, put a USGS API key in `key.txt` and run `node scripts/build_usgs_current_gwd.mjs`. The script uses the current paginated USGS Water Data OGC API, never writes the key into the CSV or browser code, and keeps one observation per site. `key.txt` is excluded from version control. This is a nationwide latest-value snapshot, not the complete historical archive.

Large national layers are handled as viewport queries so GitHub Pages does not have to ship multi-hundred-megabyte files. The gallery can load **USGS NHD streams and rivers**, **HIFLD transmission lines**, the **USFWS National Wetlands Inventory**, **FEMA NFHL flood hazard zones**, and **USGS PAD-US 4.1 protected areas** from public ArcGIS services. The streams card loads a broad bundled display network immediately—about 19,000 generalized reaches plus simplified named-river corridors—and retains a tiled live-service path for refreshes; the other national layers query their visible viewport. The stream network includes order-3 reaches at least 10 km long and order-4-or-higher reaches at least 5 km long, which adds meaningful tributary coverage without shipping the entire million-feature NHD archive. The named corridors include the Mississippi, Missouri, Ohio, Colorado, Rio Grande, Columbia, Snake, Tennessee, and other major rivers. NHD uses both `StreamRiver` and `ArtificialPath` flowline classes; named large rivers are often represented by the latter. NHD flowline records expose the source's `QA_MA` modeled mean annual flow estimate in cubic feet per second, `VA_MA` estimated velocity in feet per second, `StreamOrde`, cumulative drainage area in square kilometers, and reach length. The line width and color encodings are display-only; `QA_MA` is not a live instantaneous gage reading. The official USGS water-service-area release is linked from the gallery for users who need the unsimplified 123 MB source ZIP.

The gallery also includes **EPA wastewater treatment works** as a live viewport layer. It queries the EPA ECHO Clean Water Act / NPDES facilities service and filters to `POTW` records—publicly owned treatment works—so the map shows wastewater-treatment locations rather than drinking-water systems. Hovering a facility can show its name, city/state/county, permit status, compliance status, facility size class, reported flow, watershed, permit components, and EPA source-record URL when those values are present. This is a display/reference inventory: it is not a complete treatment-capacity model, and current operating status and capacity should be confirmed with EPA or the responsible utility.

The default view loads the nationwide USGS groundwater snapshot as an average-`gwd_ft` value heatmap and the PNNL data-center inventory as uniform dots. Density layers can aggregate record count, average measure, sum, or maximum measure, and can use blue-to-red, green-to-red, red-to-green, or single-layer-color intensity scales. The cell tooltip reports the selected value and record count. Other dense point layers use a zoom-aware display: at the country view, nearby records become count bubbles; after zooming past the national overview scale, the individual points return. Hovering a count bubble reports how many records it represents.

The repository also includes a collected-data registry at [`data/source-manifest.json`](data/source-manifest.json). It documents the current U.S. Drought Monitor GeoJSON snapshots and USGS National Water Availability Assessment (NWAA) HUC12 tables for 2020: modeled recharge/runoff/baseflow, irrigation withdrawals, public-supply withdrawals, thermoelectric withdrawals and consumptive use, and integrated availability indicators. The HUC12 tables are evidence layers keyed by watershed ID; they are not monitoring points and should be joined to Watershed Boundary Dataset geometry before polygon display. Refresh instructions and source caveats are in [`data/README.md`](data/README.md).

The refreshable [`data/historical/`](data/historical/) pack adds five complete years of NOAA Storm Events (2021–2025) and USGS groundwater-level snapshots (one observation day per month, 2021–2025), plus a collector for the five complete NWAA water years 2016–2020. It keeps raw downloads and derived CSVs together with coverage, provenance, and interpretation notes. Run the commands in [`data/historical/README.md`](data/historical/README.md) to refresh or extend the pack.

The Load data panel includes three optional **Risk analysis layers**. Groundwater change maps annual well means relative to each well's 2021 mean; drought prevalence maps annual state averages of county D1+ frequency; and natural-disaster history maps annual state NOAA event counts. Load them individually or together, then use the existing **Time lens** and **Compare layers separately** view. They remain separate screening layers and do not alter Atlas's default workspace or calculate a composite score.

The same panel now includes an optional **NWAA water screen**. It maps the validated 2020 modeled HUC12 water-availability and withdrawal records summarized to simplified HUC8 watershed polygons. The bundle exposes separate views for modeled availability, depth-equivalent surface-water flow, the source surface-water use index, and total sector withdrawals. These are basin-scale context layers—not live gage seasonality, permitted supply, or a composite competition score; older NWAA years will be added after a rate-limit-safe refresh.

Atlas also includes two separate drought-tendency views. **Drought frequency · 2020–2025** is a county-centroid density layer built from the official [USDM statistics service](https://droughtmonitor.unl.edu/DmData/DataDownload/WebServiceInfo.aspx); each cell reports the average share of 314 recent weekly observations meeting the selected D1 threshold after a minimum four-week rule. It describes recent historical frequency, not a climate-normal probability or site-specific water-supply conclusion. **NOAA monthly drought outlook** is a simplified current snapshot of the [CPC/NCEI Monthly Drought Outlook](https://www.drought.gov/data-maps-tools/us-monthly-drought-outlook), with categorical polygons for persistence, improvement, removal, development, and no drought over the upcoming month. The outlook is a forecast tendency rather than a numeric probability surface. Refresh both with the scripts documented in [`data/README.md`](data/README.md).

The map toolbar includes **Boundary lines**. Selecting **Aquifer lines** or **Both** lazy-loads the bundled USGS principal-aquifer GeoJSON coverage (`aquifers_us.geojson`); **State lines** shows the existing lower-48 state outlines. The aquifer layer preserves all 4,637 source polygon features and defaults to the six broad `ROCK_NAME` classes so the national view remains interpretable; the more detailed `AQ_NAME` field remains available in the layer data.

When an aquifer layer is selected, **Aquifer focus** appears in Layer properties. Choose a broad `ROCK_NAME` type, a specific `AQ_NAME`, or both. **Highlight matches** dims the rest of the coverage; **Show matches only** removes non-matching polygons from the map. Changing the type narrows the specific-name list.

Aquifer polygons are hoverable across their full area. Hovering raises and emphasizes the polygon and shows its specific aquifer name plus broad aquifer type.

- geometry type: point coordinates, state / region code, or source GeoJSON geometry
- latitude and longitude fields, or a state / region field
- the measure to show, plus optional label and time / category fields
- layer role, color, feature-level color field, area fill/outline style, marker size, line width, opacity, and notes

CSV files should have a header row. Atlas recognizes:

- state abbreviations or full state names in fields like `state`, `abbr`, `region`, or `code`
- latitude / longitude fields for point layers, including `lat` and `long` from `sample.csv`
- GeoJSON `FeatureCollection` geometries, which remain as points, lines, or polygons for display
- polygon coverage layers such as aquifers, protected areas, and candidate footprints; choose a broad field such as `ROCK_NAME` for distinct category colors, while detailed fields such as `AQ_NAME` remain available for inspection
- numeric measures in fields like `value`, `measure`, `gwd`, `amount`, `score`, `count`, or `total`

Wide datasets are supported: only the selected measure is rendered, so columns such as `P_1` through `P_36`, `T_1` through `T_36`, or `PET_1` through `PET_36` can become separate layers from the same file.

Point layers use a shared Web Mercator projection with the bundled lower-48 state boundaries. The `sample.csv` shape (`lat`, `long`, `gwd`) is recognized automatically: the 1,000 rows plot at their real coordinates and `gwd` is used as the default measure.

For data-center building-area work, use separate layers for candidate building footprints, transmission and road infrastructure, water or protected-land constraints, aquifer coverage, and other context. Assign each layer a role and visual style in Layer properties, then use the legend, feature colors, opacity, labels, zoom, and layer ordering to compare them. Atlas is a display and inspection tool only: it does not calculate suitability, buffers, intersections, distances, rankings, or other models. The built-in aquifer sample is illustrative rather than authoritative.

Use the map wheel or `+` / `−` controls to zoom, drag to pan, or use **Zoom to data** to fit the selected layer. Point markers stay readable as the geographic spacing expands.

Use **Presentation view** in the top toolbar to temporarily show all loaded data layers in a balanced overlay. The editing panels are hidden, the map expands to the page, and the layer index remains below the map as the presentation key. Exit with the button in the map title bar, the top toolbar, or `Esc`; the previous layer visibility and map-view settings are restored.

All parsing and rendering happens locally in the browser. The export action downloads the current SVG map.
